## Deep story analysis — themes

### What went well

- **Single server-state thread:** TanStack Query with stable **`['todos']`**, **`mapApiError`**, and mutation invalidation stayed consistent from `3-2` through `3-7`—matches `project-context.md` (no parallel canonical list in React state).
- **Tests moved with the UI:** Component tests landed alongside meaningful units (loading/error, forms, rows, shell). E2E grew per journey (list load, empty, add, row actions, reload, error recovery) rather than a single end-of-epic dump—aligned with `epics.md` mandatory bar.
- **Review feedback became concrete fixes:** Examples include broadening list-load E2E assertions (`3-2`), Playwright **`page.route` / `page.unroute` sharing the same function reference** for URL matchers (`3-7`), and **`workers: 1`** for product E2E when SQLite + one API process is shared—system-level determinism, not flaky sleeps.
- **Epic 2 contract honored:** **`GET /todos`**, **`{ todos }`**, camelCase, CORS + **`VITE_API_BASE_URL`** discipline carried through; no second REST prefix or error shape drift in client work tracked in stories.

### Struggles and surprises (systems, not blame)

- **E2E + shared SQLite:** Parallel Playwright workers and a single DB file are a natural collision; the team addressed it explicitly in config rather than ignoring ordering under load—same *class* of lesson as Epic 2’s **`--test-concurrency=1`** for API integration tests.
- **Playwright routing footgun:** Predicate matchers must be referentially stable for `unroute`—easy to miss until a test flakes or fails cleanup; now documented in story review notes for future specs.
- **Orchestration maturity curve:** Early stories noted manual parallel processes vs `webServer`; `3-7` pushed CI/local alignment (isolated DB path, CORS origin matching Playwright’s origin)—Compose remains Epic 4, but the “real client + real API” bar is met without waiting for containers.

### Technical debt and carry-forward

- **Low / bounded:** Optional future splits (smoke vs full product E2E jobs), richer accessibility audit than baseline NFR-A2 scope, any README polish as new contributors hit edge cases.
- **Epic 4:** **`/health`** and **`/ready`** remain explicitly out of scope for Epic 3—no debt against this epic’s definition.

### Testing and quality

- Vitest coverage on loading, errors, mutations, layout, and keyboard-oriented behavior; Playwright coverage on list load, empty state, add, complete/uncomplete/delete, reload parity with server, and failure + recovery with visible affordances—meets Architecture’s E2E minimum intent for core and error journeys.

## Key takeaways

1. **Journey-driven E2E alongside features** kept trust requirements (reload, recovery) visible before the epic closed.  
2. **Shared mutable state in test infra (SQLite)** requires the same discipline as API integration tests—concurrency is a design choice.  
3. **Central patterns (`mapApiError`, `queryKey`, layout shell)** reduced rework across seven stories; protecting those contracts matters for Epic 4 compose wiring.
