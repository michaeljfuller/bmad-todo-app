## Deep story analysis — themes

### What went well

- **Explicit story chain:** Prerequisites in each artifact (4.1 before HEALTHCHECK, 4.2 before compose, 4.3 before full CI story) reduced “compose merged without routes” failure mode.  
- **Health split respected:** **`/health`** process-only vs **`/ready`** DB probe matches orchestrator expectations; Compose can use **`/ready`** for **`service_healthy`** while Dockerfile **`HEALTHCHECK`** stays on **`/health`** for standalone API images—documented and intentional.  
- **Review → product improvement:** 4.2 README migrate/volume copy-paste; 4.3 follow-up ensuring compose contract test runs in **`api-integration`**; 4.4 README **## CI** corrected to match **`dev:e2e-stack`** + Playwright—docs stayed honest under adversarial review.  
- **Epic 3 retro carry-forward (A4):** Build-arg **`VITE_API_BASE_URL`** and browser-reachable API origin were treated as first-class in README, compose env, and web image build—addressing the “silent wrong API in static client” risk called out before Epic 4 image work.

### Struggles and surprises (systems, not blame)

- **Native toolchain surface area:** **`better-sqlite3`** and **glibc vs musl** choices required deliberate base image alignment (bookworm-slim, build deps in stage)—predictable class of friction for Node+SQLite in containers.  
- **Tooling asymmetry:** Dev agent environment without **Docker CLI** pushed verification to CI and human **`docker build`** smoke—acceptable when CI job exists, but highlights dependency on GHA for first signal.  
- **Story metadata drift:** Early 4.3 notes assumed “no `docker/` yet”; reality moved quickly—harmless if completion notes stay authoritative.

### Technical debt and carry-forward

- **Optional compose smoke in CI:** Documented (workflow comments + README) but not automated—tradeoff for cost; promote when team accepts runtime.  
- **E2E on compose:** Epic 3 Playwright remains on **`webServer`**-style stack; running the same suite against Compose is a future enhancement, not a gap against Epic 4 acceptance criteria.

### Testing and quality

- Integration coverage for **`/health`** / **`/ready`**; OpenAPI path assertions; root **`test/compose-docker-compose.contract.test.js`** for compose structure; **`docker-images`** job validates image builds on PRs.
